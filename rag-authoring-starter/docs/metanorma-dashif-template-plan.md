# Metanorma DASH-IF template and PDF integration plan

## Objective

Evaluate whether DASH-IF can keep the current Bikeshed/Markdown source as the
canonical source while generating a Metanorma/AsciiDoc derivative that can produce
DOC/PDF outputs with DASH-IF branding.

## Target architecture

```text
specs/<part>/<part>.bs + *.inc.md       canonical source
        ↓ generated by tool
metanorma/generated/<part>.adoc         derived AsciiDoc, do not edit manually
        ↓ metanorma compile
metanorma/output/<part>.html/.doc/.pdf  derived review/publication outputs
        ↓ publication integration
Bikeshed HTML includes PDF/DOC download links where available
```

## Immediate proof-of-concept

Part 12 is the pilot because it is relatively small and self-contained. The
current converter is:

```text
rag-authoring-starter/tools/metanorma/bikeshed_to_adoc.py
```

Current local status is documented in:

```text
rag-authoring-starter/rag/reports/metanorma-part12-poc-status.md
```

## ISO-based template approach

Metanorma Generic is attractive for a simple document model, but the local package
reported that Generic PDF is not supported. Therefore, the next PDF experiment
should use an ISO-based Metanorma document because ISO supports PDF generation in
Metanorma.

The ISO-based path should be treated as an output experiment, not as a change of
canonical source. The likely steps are:

1. Generate an ISO-compatible AsciiDoc variant from the Bikeshed source.
2. Add the ISO-required metadata fields that are absent from DASH-IF Bikeshed
   metadata.
3. Apply DASH-IF branding through the supported Metanorma customization points
   where possible.
4. If the ISO flavour cannot be sufficiently branded, evaluate either:
   - a DASH-IF-specific Metanorma flavour, or
   - post-processing of the generated DOC/PDF.

## Branding requirements to evaluate

A DASH-IF Metanorma output should ideally provide:

- DASH-IF title/cover styling;
- DASH-IF logo and organization metadata;
- DASH-IF copyright/IPR boilerplate;
- typography and heading layout similar enough to the Bikeshed HTML and existing
  DASH-IF publications;
- figure/table numbering that does not conflict with Bikeshed conventions;
- references compatible with DASH-IF and ISO/MPEG citations;
- generated DOC and PDF suitable for member review.

## Bikeshed publication integration

If Metanorma-generated PDFs become reliable, the Bikeshed publication flow should
copy PDF/DOC artifacts into the built site and expose download links from each
part. A minimal integration would be:

```text
dist/
  part12-conformance-reference-tools.html
  downloads/
    part12-conformance-reference-tools.pdf
    part12-conformance-reference-tools.doc
```

and a visible link near the top of the Bikeshed HTML, for example:

```text
Download: PDF | DOC
```

Implementation options:

1. Add a small post-build script that injects download links into generated HTML.
2. Add a Bikeshed include/metadata block that points to expected download paths.
3. Keep download links only on the generated overview page until the per-part
   integration is stable.

The preferred first step is option 3: add links on the generated overview page
only, because it avoids modifying Bikeshed-generated part HTML.

## Open questions

- Does ISO-flavoured Metanorma allow enough DASH-IF branding without creating a
  custom flavour?
- Can the workflow run reliably in GitHub Actions/Linux even though local Windows
  Generic rendering exposed a `sassc-embedded` runtime issue?
- Which outputs are required for review: DOC only, PDF only, or both?
- Should generated PDFs be published for all parts or only for mature/reviewable
  parts?
- Should generated AsciiDoc be committed or remain CI-only? Current preference:
  CI-only/generated, not manually edited.

## Recommended next tasks

1. Extend `bikeshed_to_adoc.py` with a `--flavour iso` mode.
2. Generate an ISO-compatible Part 12 AsciiDoc file.
3. Compile in GitHub Actions/Linux to avoid local Windows runtime issues.
4. Add a DASH-IF CSS/branding experiment for HTML and investigate PDF/DOC
   template customization.
5. If PDF generation succeeds, publish the Part 12 PDF as a workflow artifact.
6. Only after that, add generated PDF download links to the Bikeshed publication
   bundle.
